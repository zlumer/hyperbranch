# Task run full cycle

The vision is as follows:
1. User can launch a web interface and see the list of current tasks in the kanban.
2. User can press a button in the web ui to create a new task (with a title input and text input).
3. The task is created similar to the `hb create` command.
4. User can press a button in the web ui to launch this task into a run (similar to `hb run`).
5. Logically, user can also see the list of current runs for the task and their statuses.
6. User can press a button in the web ui next to run info and "jump into the run".
7. "Jumping into the run" opens Opencode web UI in the iframe (almost fullscreen with just a "back" button).
8. Pressing the back button returns to the main UI.
9. User can delete a run with the "remove" button.
10. When the run is started, the prompt is sent to opencode to plan the task thoroughly.
11. User should be able to customise the run prompt and agent mode: Plan or Build when they create a run.
12. User should be able to accept the run: merge the branch and delete it.

This is the MVP of working with tasks, when we have that scenario working we can actually test the workflow without the CLI workarounds and manual git commits/merges.
